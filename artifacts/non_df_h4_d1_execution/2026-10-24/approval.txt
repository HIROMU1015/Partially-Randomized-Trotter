## 2. 研究目的

固定H4では、以下の回路単価が保存されています。

| 表現 | PF | PR（256本平均） |
|---|---:|---:|
| Pauli-JW | 255,500 | 9,321.10 |
| DF-native | 135,355 | 23,678.44 |

単位：compiled RZ数/shot。

**PFではDF-nativeが安いのに、PRではPauli-JWが安くなる原因を、回路構造に基づいて定量的に調べます。**

特に、

- Pauli-JW PRでZ/ZZの保持部分がどれだけ安いか
- Pauli-JWとDF-nativeのrandom event部分の違い
- DFのbasis変換・controlled演算の費用
- Full回路と部分回路のcompile結果の非加法性

を調べます。

今回のD1は、代表4構成による機構診断です。

256 trajectoryの平均費用の因果分解や、Hamiltonian表現そのものの一般的な優劣を証明するものではありません。

## 7. D1の段階的実行

### Stage A：4つのfull回路を再構成

保存descriptorだけを使い、4つのfull入力回路を再構成してください。

各回路について以下を照合します。

- 保存trajectory／event ID・hash
- Pauli／DF descriptor
- Gate順序・qubit順・角度
- Basis・control構成
- Global／relative phase
- Compiler設定
- 元のrecursive input fingerprint

**4つのfull回路すべての旧fingerprintが一致してから、費用compileへ進んでください。**

自動gate名だけによるhash不一致が疑われる場合も、勝手にrename・hash仕様変更・field無視を行わないでください。

不一致があれば、その差が科学的な回路同等性に関係するかを報告し、今回の契約ではSTOPしてください。

意味的同等性に基づく別の再現性基準を使う場合は、別途契約変更と承認を必要とします。

### Stage B：full4構成の費用compile

Stage AがPASSした場合のみ、4つのfull wrapperを元の固定compiler設定でcompileしてください。

以下の旧RZ数との完全一致を確認します。

- Pauli PF：255,500
- Pauli PR index0：9,652
- DF PF：135,355
- DF PR index0：23,021

**1つでも不一致の場合は、その時点でSTOPしてください。**

失敗結果と実行証拠は保存します。

旧費用と不一致の回路を使って部分回路の原因分解を進めないでください。

自動retryや別trajectoryへの差替えは禁止です。

### Stage C：部分回路の費用compile

Full4構成がすべてPASSした場合のみ、残り5構成をcompileしてください。

- Pauli PR retained-only
- Pauli PR event-only
- DF PR retained-only
- DF PR event-only
- Empty wrapper

Phaseの所有規則は前段階の契約を維持してください。

Retained-onlyには決定論的保持部とそのphase、event-onlyには保存event列と対応するphaseを含めます。

Event-onlyから保持部を削除したことを理由に、元のevent occurrenceを新しいbasis最適化で手動結合しないでください。

これらはunitaryが変わる診断ablationであり、新しい正規のPF/PR実装として扱いません。

## 9. 費用構造の解析

Stage Cまで完了した場合、RZ数・CX数について以下を評価してください。

`C_F`：Fullのcompiled費用

`C_R`：Retained-onlyのcompiled費用

`C_E`：Event-onlyのcompiled費用

`C_0`：Empty wrapperのcompiled費用

比較量：

```text
retained_increment = C_R - C_0

event_increment = C_E - C_0

isolated_prediction = C_R + C_E - C_0

Delta_interaction = C_F - C_R - C_E + C_0

contextual_event_increment = C_F - C_R

contextual_retained_increment = C_F - C_E
```

負の値もそのまま保存してください。

**`Delta_interaction`を単純に「compiler最適化の効果」と断定しないでください。**

この差には、部分回路の接続、制御化、位相、wrapper、コンパイル最適化などの相互作用が含まれます。

また、これらの量を一意な因果寄与率へ無理に変換しないでください。
