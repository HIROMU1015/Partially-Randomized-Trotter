## 3. 将来の処理順序とGO/STOP

| phase | 入力と処理 | 次へ進む条件 |
|---|---|---|
| input_reference | 保存snapshot。sector完全性、各a†Gaの保存性、state/bit順、full/sector全column、DF再構成、expm/eigh参照 | identity・norm・sector・参照の登録gateが全てpass |
| correctness | 全DF blockについて正負時間、保存state＋36 sector column。登録8 cellのnative actionと独立dense oracle | primitive lowering、global S2/S4、finite corrected/raw・B、B0 signed分解が全てpass |
| wrapper_cost | 既存samplerの4 trajectoryを共有replay。ordinary/directional、legacy replay、測定付きwrapper 28件 | 全件照合・compile・出力が上限内で完了。終端後STOP |

spin sectorの証明はfull Hamiltonianのnet保存性だけに依存しない。
one-bodyと全Gについてcross-spin coefficientが**厳密に0**であることを要求する。
近似0でもSTOPし、係数を落としたりsector政策を自動変更したりしない。
保存sectorは既存`PhysicalSector`の完全な列挙と一致させる。
native Gaussian gateの途中にはprojectionを挿入せず、full Qiskit vectorで一つのblockを作用させた後にleakageを検査する。
この区別により、basisの中間gateまでspin保存を仮定する誤りを避ける。

norm/leakageは1e-12、native/dense・control/legacy一致は1e-9、expm/eigh state差は1e-10をtechnical gateにする。
保存stateのexact phase-surrogate residual allowance `|T|ρ`にも1e-9 gateを置く。
thresholdはengineering条件で、精度保証の定理として扱わない。

主参照は保存stateへのdense exponentialで、Rayleigh phaseを無条件にexact targetへ代入しない。
expm/eigh差、Rayleigh residual、phase-surrogateとのsignal差を別々に保存する。
`|T|ρ`はexact Hermitian evolutionについてのsurrogate allowanceで、floating-point誤差を含まない。
二つの浮動小数点法の一致も、共通誤差を除いた証明にはならない。
したがってpilot outputは常に`numerical_allowance_certified=false`、accuracy eligibilityは`UNDETERMINED`とする。
**精度適格・必要shot・総資源の順位を主張するには、別段階で総数値allowanceとheadroomを確定する必要がある。**

## 5. 実行上限とenforcement

これは認可を求める際の**H4限定上限案**で、今回のCPU/RAM割当ではない。
H6を除いた3 phase×900sとして総wallを2700sへ縮小し、v2全体14,400sを使い回さない。

| 上限案 | 値・enforcement |
|---|---|
| science worker / CPU / threads | child 1、割当CPU 1、BLAS/OMP/MKL/Numba/Qiskit等1。parentは監視のみ |
| address space | child RLIMIT_AS 8 GiB。RSS上界とは呼ばない |
| wall | phase 900s、総2700s。独立parentが0.05s間隔で監視しprocess groupをkill |
| output | 512 MiB。結果write前に総byteを検査、親終端分をreserve。child RLIMIT_FSIZE、aggregate監視、logは64 KiB以内 |
| compile / trajectory / occurrence | 28 / 4 / 16。呼び出し前counter、成功済みrecord数を別に保持 |
| signal action | tail corrected＋raw計896、deterministic 100,000、各action前にcounter |
| reference | per dense reconstruction 20,000 matvec、全linear-operator matvec 10,000、呼び出し前counter |
| validation action | primitive 2,000、control probe 200。各callback前にcounter |
| wrapper size | untranspiled 1,000,000、transpiled 5,000,000 Qiskit instructions |

schedule/circuitのallocation前に既存native構造上界を使い、作成後に実sizeを再検査する。
legacy replay oracleも作成前・後に上限を検査する。
transpiled-sizeは既存cost APIが戻った後の検査であり、compiler中のnative memory/timeはRLIMIT/watchdogで制限する。
dense eigensolver内部の演算をlinear-operator matvec数へ偽って加算せず、wall/address-space制限を適用する。
aggregate disk監視とwallはpollingのため、外部native処理には一監視間隔内のovershootがあり得る。
OS filesystem quotaとしての絶対aggregate disk保証は今回実装していない。
自分の結果writerとparent logはwrite前に制限し、途中記録を消さずSTOPする。

H4 complex128 full dense matrixは1 MiB、system stateは4 KiB、ancilla込みstateは8 KiBである。
これは配列の理論サイズで、実測peak memoryではない。library import・Gaussian gate展開・compilerには別の費用がある。
今回H4 denseを使うのは小規模correctness oracleだけで、H6/H8のdense拡張を認可・実装していない。
