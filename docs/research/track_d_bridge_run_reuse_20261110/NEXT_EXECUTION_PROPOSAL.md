[結果](REPORT.md)。今回の追加開発はケースB：run内部の再走査とCX feedを減らして1.15〜1.33倍高速化したが、反復数・最悪計算量は不変、RSSもq8で増えた。この一方式で技術検証を区切る。新たな方式を追加して速度改善を追い続けない。

## 構造評価器を保全する理由と限界

固定q4/q8の8 wrapperで各epochの列・位相・全56資源が再現できるため、有限の校正点・価格モデルの整合性検査には有用である。一般P0再実装を必要とせず、新P0なしで保存nativeを軽量に再計数できた。この用途の資産として旧版と改善版を両方残す。

ただし長q向けにさらに進めるには、全unit epoch、CX frontier再構築、tuple/object保持、raw QC入口を解決する必要がある。局所worklistへの全面移行は依存graph・順序管理・phase処理の複雑化を伴う。今回の1.3倍程度の改善だけでは、その開発費用を正当化したことにならない。q1024〜4096の新計算を提案の既定実行にしない。

## 推奨する重点移行案

改善版を有限検査器として保存し、既存A主／F frozen／S探索モデルの適用条件・長q不確かさを明示したうえで、PR＋RPE全体のアルゴリズム共同最適化へ重点を移す案を推奨する。構造評価器の完全互換追求を研究の主目的にしない。A/F/S自体のfit・変更、shot数・13-round総費用の再計算は今回実施していない。

次に必要な最小作業は、どの科学的探索変数・誤差余裕・価格proxyの不確かさが最終判断を左右するかを整理して、既存モデルの利用範囲と必要最小限の検証条件を定めることである。数値的な共同最適化や新校正は別の明示実行範囲を要する。詳細科学レビューも自動開始しない。
