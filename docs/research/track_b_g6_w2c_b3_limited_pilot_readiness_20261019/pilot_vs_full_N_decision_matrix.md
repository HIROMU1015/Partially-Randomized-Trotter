# Pilotと全Nの判断表：未採択

|将来pilotで分かること/残ること|全N判断への入力|
|---|---|
|固定4方式の実入力でgenerator/監査/angle/保存の入口と意味論が通る|入口確認のためだけの全Nは不要と判断し得る|
|観測prefixでCPU支配項、Fullのlocal law/rational/requery overheadが識別できる|限定的な古典費用説明を目的とするなら全N不要と判断し得る|
|観測したpathで比較差が大きく、CPU分解能/observer/並列競合を分離できる|固定prefixの記述的比較として報告可能。母平均・全N総額とはしない|
|raw-zero/coin-reject/acceptedの必要pathが未出現|未検証と報告。追加scopeの必要性はユーザー/GPT判断。自動samplingしない|
|短いCPU時間・setup支配・高いblock変動・observer負担でonline順位を識別できない|事前設計を改めた長いpilotや比較条件が必要か判断。直ちに全N必須ではない|
|全N実workloadの直接CPU/wall、保存総量、長時間memory/IO挙動が研究の主要結論に必要|全N直接実行が必要になる候補。ただし別SOURCE/証拠粒度/authorizationを要する|
|path率/整数bit長/GC/cache/IOがprefixで安定せず外挿仮定を支持できない|全N総量を主張するなら直接観測等が必要。無条件の線形外挿は不可|
|量子軸confidence/Full-N completion自体の確認が論点として残る|小pilotは代用しない。科学的必要性を別途判断|
|pilotがSTOP、unknown、科学不一致になる|正常費用比較へ入れずSTOP。retry/Full-Nへ自動移行しない|

外挿を行うなら固定path頻度、整数bit長分布、setup回数、observer、retention、並列競合、runtime/負荷条件が代表的という仮定を明記する。`setup + N × observed online/call`は条件付きのモデルに過ぎない。pilotのCPU記述を量子confidenceや機械非依存の方式順位に読み替えない。
