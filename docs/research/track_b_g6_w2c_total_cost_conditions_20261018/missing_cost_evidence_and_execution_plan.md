[入口](README.md) / [条件式](break_even_conditions.md) / [引継ぎ](handoff.md)。**計画資料であり、科学実行許可書・契約・run manifestではない。** 入力、値、実行先、call数を今回新たに採択していない。W2c-B/Cは未実施である。

## 1. 既存情報の再利用と最小依存関係

登録済みdevelopmentケースに限定して[G7結果報告][G7R]の既存conditional期待T結論を引用するなら、同じN/受理率/event価格を取り直す必要はない。短い固定SHA traceを全N CPU期待費用へ外挿してはいけない。G8のfinite cold/warm履歴は利用できるが、新しい完全cache coverageや独立再現ではない。

最小の順序は、ユーザーが判断したい**費用座標と対象scope**を選ぶ→既存値で足りるか確認→不足する枝だけ取得、である。B1だけで全費用は決まらず、B2だけでも物理価格は決まらない。

| 枝 | 依存関係・最小範囲 |
|---|---|
| B1 N | 固定input/policyと既存budget。新入力なら入口充足とNの具体評価が必要。既存同一ケースは引用で足りる |
| B2 digital law/IR価格 | B1と共通identity。logical座標ならC1不要。正確な小support referenceの既存範囲、又は認証要約だけで足りる場合がある |
| B3 古典profile/peak/output | 固定Nと全N schedule・保存仕様。CPU/bit/memoryは別取得。F3対称入口の未実装を先に解決する必要がある |
| C1 native provider | B2のevent/price依存性、固定physical provider/compiler/error/key。必要な座標だけ取得。CQを抽象のままnative総費用としない |
| C2 実行層 | B1/B2とstate/readout/backend/all-N accumulator/cache/failure方針。C1と結合し実装・総費用を扱う場合に必要 |

全event列挙・全key合成・全N実測を最初から要求しない。一方、未知部分を無料oracle、0費用、IID実証済みとして省略もしない。どの枝でも、SOURCE変更が要る場合は別途実装指示→固定→必要な検査→科学実行承認の順序を要する。今回その実装・契約準備を開始しない。

## 2. P5Closedを将来比較する場合の差分

[W2b比較表][W2BM]をそのまま引き継ぐ。P5Closedはm=5の別G9 budgetであり、bias・confidence・log・axes・provider failure割当等がG7と異なる。共通finite operator/入力、root/dyadic/angle/provider規約、zero/estimator、ε/残余幅、confidence/familywise、取得費用・出力・失敗規則を明示的に揃える必要がある。今回は共通budgetを作らず、Nや総費用を混合しない。形式P5＋tailは実装samplerではない。

## 3. 承認境界・STOP

次の担当は**ユーザー**：既存の限定証拠で判断するか、どの座標について追加取得するかを決める。**Codex**は具体的な対象・固定SOURCE/入力・precision・科学call・保存先・STOP・既存契約との差分について別途明示指示を受けてから作業する。未採択のconfidenceやscalar費用価格を補わない。

新しい計算契約を準備する場合、共通指示§8.4に従い恣意的なCPU/RAM/worker/wall上限を置かず、利用可能資源と非干渉・加速を確認し、必要なoutput/log/call/instruction制限を定める。ただし**既存固定契約の制限は変更しない**。科学的retry/one-shot条件も別途定める必要があり、旧消費済みgrant/claimは再利用しない。

本計画には実行許可・新契約採択・authorization/grant/marker/claim発行はない。**mandatory STOP**。
