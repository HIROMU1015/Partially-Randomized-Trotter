# 次の判断材料：継続とA/F/S利用の両案

[結果](REPORT.md)／[実装](IMPLEMENTATION.md)。今回の目的である同一ruleの高速化・省メモリ化は達成した。ただしround数と全列走査は残り、q1024〜4096の実用性は未認定である。正式採択はユーザー／GPTへ戻す。

## 構造評価器を限定継続する技術的根拠

q4／q8の各Strong／Reference X/Yで、旧新の最終word・wire・parameter bit・旧binary64 phase・MPFR160 phase・各round・全7資源が固定保存結果と一致した。新P0なしで実測の改善が得られたため、完全P0互換を作らなくても、科学計算の価格検査・将来の校正点を安く取得する技術資産にはなった。

続ける場合の焦点は、同じround／flush順を再現しながら、変更のない部分の再走査を減らせるかである。worklist／epoch付の局所再処理、compact native記述、caller所有QCを不要にする上流emitter等が候補。ただしrunの結合順、matrix積順、phase項順、CX連鎖、global word順を保つ必要があり、単に数学的に同値な別最適化を足す作業にしない。

次の最小技術検証を許可する場合は、保存人工列と今回のq4/q8 native列に限定する。旧新exact差分・時間・RSSを先に確認し、SOURCEと初回失敗を保持する。新sampling／P0／whole-path生成／q16以上／H変更／fit／N／13-roundは含めない。semantic／phase／rule不一致は依存処理を停止し、閾値緩和でPASSにしない。公開照合後STOPする。この追加実装は今回自動開始しない。

## A/F/S＋PR全体共同最適化へ重点を移す根拠

新engineもO(RL)時間・O(L)記憶で、最悪O(L²)。今回の一致は二つの固定pathであり、全PR lawの期待価格・母平均・全q P0閉包やRPE成功条件は保証しない。raw QPY保持とgate.definition cache、phase局所出力の精度、routing／合成精度の費用も残る。これらの全面閉包を目標にすると、compiler開発が科学目的を圧迫するおそれがある。

したがって、既存A主／F frozen／S探索モデルを条件付き価格proxyとして保ち、改善した構造評価器を有限校正・整合性検査に使いながら、PR＋RPE全体の共同最適化を別scopeで進める案は合理的である。今回A/F/Sを再fit・正式変更したり、N／全13-round総費用を更新したりしない。
