### B2. 四方式のmapping

固定方式：

1. Ordinary
2. Partial Return + ordinary tail
3. Closed P3 + ordinary tail
4. General Full Return

各方式のLayer A/Bを確認してください。

サーバー側の静的mapping候補：

| 方式 | Layer A | Layer B |
|---|---|---|
| Ordinary | G7 canonical generator | LegacyEndpoint系の監査・再照会 |
| Partial Return | G7 canonical generator | LegacyEndpoint系の監査・再照会 |
| Closed P3 | G7 canonical generator | LegacyEndpoint系の監査・再照会 |
| Full Return | FullReturnGenerator | F3 facade／session |

このmappingを独立に検証してください。

特に以下を確認してください。

- Canonical 3方式に、存在しないF3 facadeを仮定していないか。
- F3.prepareの正入力canonicalケースでの拒否境界。
- Full Returnのevent/packet/child生成関係。
- CanonicalとFullでLayer Bの監査経路が異なること。
- Source上で提供される機能と、今回の人工surrogateだけが提供する機能の区別。

### B3. Result・event・weight

次の型・意味論を静的に確認してください。

- Word / raw word
- Exact rational
- Proposal / coefficient / weight
- Child identity
- Raw event
- Reduced/nonreduced

`Fraction`等のexact representationを、浮動小数点値へ黙って変更しないこと。

### B4. F3・codec

F3のEvidence、Failure、trace、angle等のSOURCE上の契約を確認してください。

F3独自のexact codecと、既存driverのcanonical codecがbyte互換であると無条件に仮定しないこと。
