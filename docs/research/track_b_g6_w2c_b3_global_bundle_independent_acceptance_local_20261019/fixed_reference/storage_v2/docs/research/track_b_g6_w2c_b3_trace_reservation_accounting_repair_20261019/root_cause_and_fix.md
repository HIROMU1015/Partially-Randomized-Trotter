# 根本原因と修正

旧版はstatefile更新→fallible trace保存→schedulerのcounter/cursor/ticket更新という順序だった。trace例外が、既に予約されたslotと後段の会計を分断した。同じwrapper方式はENTERやcoalesced COMPLETEにも例外境界を挟む。

新Coordinatorは旧SOURCEを継承元として保持し、予約/ENTER/terminal/coalesced handlerを新versionへ実装した。RAMの予約counter、pair cursor、current ticketを一つの非I/O更新として確立し、authoritative RAM stateも更新する。その後に物理state保存・traceを試す。保存notificationは会計更新の途中へ例外を返さず、STOPと明示的なevidence failureへ伝える。

- RESERVE保存失敗でもslot/counter/cursor/ticketは予約済み。新たなENTERは許可しない。workerが許可を受けず終了したslotは開始前取消として保持する。
- ENTER traceが失敗した場合はstarted0、開始前取消。START_RESERVEDを実body entryへ昇格させない。state保存がENTER途中で失敗した場合も、許可は返さず、物理state証拠の不完全を明記する。
- COMPLETEはtrace保存成功前にCOMPLETEDへ進めない。COMPLETE記録失敗はUNKNOWNになり、未証明の成功を加算しない。F01自体は旧driverのまま。
- FAIL/CANCEL/UNKNOWNとEOF cleanupも、notification例外がticket解放・counterを分断しない。reserved UNKNOWNは実body entryの証明ではない。
- coalesced WRITE_ACKは観測counterを先に検証・更新し、その後にtraceへ通知する。範囲外ACKはcounterを変更する前に拒否する。前trial COMPLETEと次RESERVEを区別し、保存失敗後は次の予約へ進まない。

複数fileとRAMの完全なatomic更新は主張しない。statefile pwrite自身が失敗した場合、RAMのnonrefundable intentと物理証拠を分ける。V2のstatesはauthoritative RAM shadow、statefile_complete=falseとstate_errorsは物理一致を認証できないことを示す。completefalse、補助検証INCOMPLETE_EVIDENCEとし、rawをstate一致PASSへ作り直さない。shadowは1 byte/planned slotの追加RAMで、保持logを二重課金しない。

成功markerはreceipt・診断fileのwrite/flushとadmission STOPの保存が済んだ後にだけcontrol journalへ出す。途中のsummaryや孤立receiptを全run成功の証明にしない。close故障も結果へ反映する。既存STOPがあるcleanupで、閉じたjournalへ不要な二度目のSTOP保存を試みない。
