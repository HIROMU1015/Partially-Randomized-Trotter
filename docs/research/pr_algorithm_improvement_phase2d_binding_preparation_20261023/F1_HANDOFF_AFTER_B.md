# B後にF1へ渡すものと残る承認

B成功時に渡すのは、physical/catalog input、S/P alternatives、四arm atoms／exact lambda／L／I/u/s/v、F1とcatalogのlaw metadata/API tolerance、source/env layer identities、input-only F1 bundle、case range/count descriptors、全attempt/completion/STOP記録である。F1の正しさや資源優位を渡すのではない。

F1の `E_a=L_a+L_a^3`、sum E、component probes `3sum L` を実B結果から計算する。固定枠は8motif×4arm、96controlled motif builds、64full-wrapper compile requests、136catalog controlled builds。これらの科学処理はBで実行しない。現在のL/Eを推測しない。

BはF1.LAW.{arm}.{ordinal}等のrange descriptorを出すだけでevent payloadを生成しない。実行用F1 case inventoryの展開・payload/依存DAG、価格recipe／interval資格、full F1 environment、API/finite-bit/bias条件を別途freezeする必要がある。入力コピーだけを許可と読み替えず、追加処理をfinal契約へ明記する。

F2のQ=2sum L²、logical full-wrapper requests Q+2はBのLから決定可能。unique compile misses U_F2はnull／UNRESOLVED_UNTIL_IR_BINDINGとし、回路を作ってB中に埋めない。F2 K0数値law／angles/B/Nは未生成、F1 K2の値を流用しない。全trajectoryを少数MCへ無断変更しない。

basic Bの価格はPRICE_PROVIDER_UNBOUNDで、F1承認準備は完了しない可能性がある。その場合はrecipe build／intervalの対象と回数を別承認へ返す。B成功からF1実行へ自動移行しない。F1後もSTOP、ユーザー/GPT確認後にF2を別途明示承認する。
