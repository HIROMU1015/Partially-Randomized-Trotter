# Codex指示：Hamiltonian Simulation新規アルゴリズム研究・初期探索検証

## 1. 目的

量子コンピュータによるHamiltonian simulation、特に量子化学シミュレーションについて、新しいアルゴリズムの改善・提案につながる研究方向を探索する。

これまでPartially Randomized Trotter（PR）を研究してきたが、今回の目的はPR内部アルゴリズムの改良に限定されない。

対象となるのは、例えば以下である。

- Hamiltonianの分解・変換・再構成アルゴリズム
- PRに適したHamiltonian構造を生成するアルゴリズム
- Hamiltonian表現とPR内部処理を一体として設計するアルゴリズム
- PR以外のHamiltonian simulation手法にも利用できる新しい構成法
- 既存アルゴリズムの限界を解消する新しい理論・構成原理

ただし、PR内部のRTE、sampling probability、return aggregationなどを単独で改善する研究は、別のTrack Bで進めているため、今回の研究対象から除外する。

**今回の研究では、既存手法の単なる組み合わせやパラメータ調整ではなく、新しいアルゴリズム・構成法・理論的知見につながる課題を探したい。**

現時点で研究の中心仮説や採択アルゴリズムは決まっていない。

初期検証を通じて、複数候補の成立可能性、改善機構、問題点、発展の余地を明らかにすることが今回の目的である。

## 4. 今回の初期検証で扱う研究候補

以下の3方向を出発点とする。

ただし、これらに研究テーマを限定するものではない。

### 候補A：Hamiltonian分解と決定論・乱択処理の同時設計

中心となる研究課題：

**既存のHamiltonian分解から決定論部分を選ぶのではなく、決定論側と乱択側がそれぞれ安価に実装できるような分解そのものを構成できるか。**

検討内容：

1. 既存DFのfactorを変換する自由度を確認する。
2. Factor空間の直交変換などによってHamiltonian全体を保存できる条件を確認する。
3. 既存のrank選択・weight rankingと数学的に同値になる条件を特定する。
4. 同値にならない場合、どの物理的・アルゴリズム的な指標に差が生じるか調べる。
5. 決定論側の交換子構造、乱択tailの実際の係数1ノルム、基底変換費用、回路資源を区別する。
6. 共有基底を利用できるblockと、正確に保持した残差による構成も検討する。

特に、Frobenius normなど既知のproxyを改善しても、PRの最終費用が改善するとは限らない点に注意する。

**最初の重要な問いは、既存の単純なfactor選択では得られない、実装・誤差上有利な分解構造が存在するかである。**

数値的に有利な例だけでなく、改善できない条件や反例も重要な結果として扱う。

### 候補B：補助空間の漏れを抑える圧縮Hamiltonian表現

中心となる研究課題：

**補助軌道などを利用したHamiltonian圧縮表現について、物理部分空間へのleakageを抑えながら、圧縮による量子計算資源削減の利益を残せるか。**

共有Markdownで提案された、物理部分空間への射影 \(P\)、反射 \(S=2P-I\) を利用する構成を確認する。

\[
\overline H=\frac12(\widetilde H+S\widetilde H S)
\]

まず以下を区別して検証する。

1. 物理部分空間でHamiltonianが保存される条件
2. 生成子の対称化と、完成した時間発展演算子の平均との違い
3. RTEの補正平均演算子の性質
4. 個々の乱択回路におけるleakage
5. 有限Taylor打切り・正規化による信号減衰・sampling誤差
6. Reflection・補助qubit・制御操作の実装費用

群平均やsymmetry protectionそのものを新規アルゴリズムと主張しない。

重要なのは、既知の保護手法とは異なる構成上の利益が存在するか、また実際の圧縮Hamiltonianへ接続できるかである。

必要なら、PRを使わずに物理部分空間を保存する圧縮分解の可能性も検討する。

### 候補C：近可積分構造を利用できるHamiltonian分解の構成

中心となる研究課題：

**THRIFTなどの構造利用型Hamiltonian simulation手法が要求する、安価に実装可能なblockをHamiltonianから構成できるか。**

検討内容：

1. \(H=A+\alpha B\) などの分解を考える。
2. \(A\) の可解性と実装費用を区別する。
3. 必要な混合propagatorが実際に安価に構成可能か確認する。
4. 共有固有基底、可換block、低次元演算子代数などの利用可能性を調べる。
5. 単に\(\alpha\)やcommutator normを小さくするだけの最適化と、新しい実装可能な分解構成を区別する。

混合propagatorを正確または十分な精度で実装する費用が、アルゴリズム上の理論的利益を打ち消す可能性を重視する。

## 5. 実施手順

### Phase 1：既存source・数学的構成・検証可能性の確認

まず共有MarkdownとRepositoryを確認し、各候補について次を整理する。

- 何を改善しようとしているか
- 数学的に保存される量
- 改善が生じ得る自由度
- 既知手法と同値になる条件
- 改善できない条件・反例
- 既存実装で確認できること
- 新しい実装が必要なこと
- 比較すべきbaseline
- 最小限の検証によって判別できる仮説

既存sourceの実装と、研究文書に書かれた提案を区別する。

また、最初に簡単な数学的検査で否定できる仮説については、無理に大規模な数値実験を行わない。

### Phase 2：小規模な機構検証

Phase 1で検証可能と判断した仮説について、必要最小限の数学的・数値的な検証を実施する。

検証方法の詳細はCodexが設計してよい。

例えば、

- 小規模行列による恒等式・不変性検査
- 可換・非可換toy modelによる比較
- Factor変換の成立条件の確認
- 改善が期待される例と反例の構成
- 物理部分空間への漏れの評価
- 必要な回路primitiveの実装可能性検査
- 既存sourceを利用した小規模な回路資源比較

などが考えられる。

ただし、これらをすべて実行する必要はない。

**今回の初期検証で最も重要なのは、計算回数ではなく、改善機構の有無について情報が得られることである。**

検証対象の分子、basis、toy model、評価指標を最初から固定する必要はない。各仮説の成立可能性を確認するのに適した条件を選び、その選択理由を記録する。

比較では同じ物理問題、精度条件、資源会計を用いる。条件が一致しない比較は探索的な診断として区別すること。

回路の代理指標、compiled cost、測定回数を含む総資源費用も混同しない。

### Phase 3：改善機構の評価と候補の整理

各候補について、次の項目を記録する。

1. 仮説の内容
2. 実施した検証
3. 数学的に確認できた性質
4. 数値的に確認できた性質
5. 改善が生じた条件
6. 改善が生じなかった条件
7. 既存手法との差分
8. 未解決の問題
9. 新規アルゴリズムとして発展する余地
10. 次の検証で明らかにすべきこと

改善が確認されなかった場合も、その原因を可能な範囲で分析する。

ただし、限られたtoy modelの結果から一般的な不可能性を主張しないこと。

また、探索的な結果から新規性や論文化可能性を確定しないこと。

### Phase 4：研究候補の比較資料作成

検証結果を踏まえ、各候補について以下を比較する。

- 科学的意義
- 既存研究との重複・差分
- 数学的な成立可能性
- 実装可能性
- 量子資源削減の可能性
- 古典前処理費用
- 研究としての発展性
- 追加検証に必要な労力
- 主な失敗要因
- 未解決事項

改善率だけで順位を決めない。

**次にGPTが研究方針を判断するための証拠と論点を整理することが目的であり、Codex自身が中心研究を確定することは目的ではない。**

## 7. 検証の品質と注意事項

以下を厳守する。

- 理論上の恒等式と数値実験の結果を区別する。
- Synthetic testのPASSを科学的仮説の支持と混同しない。
- 既存研究の方法を再実装しただけで新規性を主張しない。
- 既存コードの誤差や旧結果を、検証済みの新しい結果として扱わない。
- Exact dataを使用した開発・診断と、未知データでの検証を区別する。
- Ground-state情報を使用した最適化は、truth-freeな方法とは区別する。
- 量子回路の追加操作や測定費用を無視した資源改善を最終的な改善と呼ばない。
- Hamiltonian近似誤差と時間発展近似誤差を区別する。
- 新しい数式が既知の数学的恒等式に還元される可能性を確認する。
- 単純な例の改善を一般的な量子化学Hamiltonianへの改善と外挿しない。

特に重要なのは、**実際に何が新しくなったのかを明確にすること**である。

既知の演算子を別表現で書いただけなのか、新しい構成自由度があるのか、既存手法が扱えない条件を扱えるのかを区別する。

## 8. Codexの裁量と実行範囲

今回の指示は、初期探索と小規模な機構検証を一つの作業として依頼するものである。

Codexは以下を自律的に決定してよい。

- Source確認の順序
- 数学的な検査方法
- Toy modelの選択
- 既存実装の再利用方法
- 最小限の検証コード・テストの設計
- 小規模数値実験の具体的な条件
- 初期検証に必要な補助資料
- 技術的な不具合への対処

細かな作業ごとにGPTの承認を要求する必要はない。

一方、以下は今回の作業範囲に含めない。

- 研究テーマを一つに確定すること
- 中心仮説の採択
- 大規模な分子ベンチマーク
- 全候補の網羅的な資源最適化
- Track BのPR内部アルゴリズムの変更
- 既存の重要な研究結果・STOP分類の変更
- 新しいアルゴリズムの新規性や論文化可能性の最終判断

計算費用が大きくなる場合は、resource guardや実行上限を設け、技術的に妥当な小規模検証へ縮小する。

十分な情報が得られない候補について、無理に肯定的な結論を作らない。

## 9. GitHubへの保存

検証結果は、後からGPTが独立して確認できるように保存する。

必要に応じて、以下を残す。

- 検証に使用したsource
- 入力条件と比較条件
- 数値結果・一次データ
- テストとvalidation結果
- 実行ログ・実行環境・resource audit
- 数学的な確認内容
- 反例・失敗結果
- 候補ごとの検証報告
- GPTレビュー用の証拠索引

Source、入力、結果、検証コードの対応を記録する。

既にremoteに存在する資料は重複してcommitしない。新しく作成・変更した対象ファイルだけを明示的にstageし、無関係な変更や機密情報を含めない。

Force pushや無関係なファイルの一括stageは禁止する。

Commit・push後は、remote上のbranch・commit・主要ファイルを再取得して確認する。

単に「ローカルで保存した」「pushに成功した」だけでは、GPTが取得できる証拠が揃ったとは扱わない。

## 11. STOP条件とGPTへの引継ぎ

次のいずれかの状態になったら、今回の探索検証を一区切りとして停止する。

1. 初期検証で主要候補の成立可能性を比較できる材料が揃った。
2. 重要な数学的な障害・反例・改善機構が見つかった。
3. 検証を続けるには、中心仮説や研究方針の変更が必要になった。
4. 次に必要なのが、大規模な数値検証や重要な科学的判断になった。
5. 実行環境・証拠不足などにより、初期検証を継続できなくなった。

重要な結果が得られた場合、その結果を踏まえてGPTによる研究レビューを行う。

ただし、Codexの最終報告だけをもってGPTレビューが完了したとは扱わない。

**最終成果物は、特定アルゴリズムの採択ではなく、研究方向を科学的に再評価するための、追跡可能な初期検証結果一式とする。**

今回の作業では、研究候補の探索可能性を維持し、改善が確認されなかった方向についても、その原因と学術的な意味を可能な限り整理すること。
