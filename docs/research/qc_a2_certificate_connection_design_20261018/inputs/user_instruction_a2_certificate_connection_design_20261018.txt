# Codexへの指示：A2有限step保証の認証情報接続仕様・比較契約の設計

## 0. 目的と今回の作業範囲

④「PRに限定しないアルゴリズム改善研究」において、有限step相対形式保証A2の実用性を判断するため、**固定DF Hamiltonianを対象とした認証情報の接続仕様と、公平な比較契約を設計**してください。

直前のpreflightは、

`INPUT_CLASS_FOUND_CERTIFICATES_INCOMPLETE`

で完了しています。

固定粒子数sectorの一体項＋符号付きDF平方に対し、条件付きでPSD化できる既知の方法と、Gaussian・controlled S2の既存回路部品が確認されました。

一方、同じHamiltonian・sector・分割に対応する以下の認証情報が不足しています。

\[
L,\ U,\ W,\ f_j,\ \Lambda,\ K_{\mathrm{SOS}},\ \overline C_2
\]

今回の目的は、**これらを正しく生成・検証・保存し、RF0/RF1/EW2と強い既知対照へ接続するための技術仕様を作ること**です。

### 承認範囲

実施してよい作業：

- 既存SOURCE/API・保存資料の読取り
- 認証情報の入力・出力仕様の設計
- 証拠生成・検証手順の設計
- 既存SOURCEとの接続方法の整理
- 比較契約・費用台帳の設計
- 必要な静的検査と文書作成

実施してはいけない作業：

- 新規科学計算・保存科学数値の再解析
- 実際のcertificate生成
- 新しい数学的定理・保証の探索
- 科学SOURCEの実装
- PF/QPE simulation・native compile
- 新しい科学レビュー
- A2の正式採択
- authorization・grant発行

**今回は設計作業であり、科学実行の承認ではありません。**

## 2. 今回の暫定比較契約

次の方針を**技術設計の暫定前提**として使用してください。

まだユーザーが正式採択した科学実行契約ではありません。

| 項目 | 今回の設計前提 |
|---|---|
| 対象 | 固定されたDF Hamiltonian |
| 分割 | 実装可能なPSD fragmentによる固定順序の対称二次PF |
| Sector | 最初は固定粒子数Nを優先 |
| 保証 | DFモデル内での認証付き有限step保証 |
| Ground state | exact ground状態への条件付きaccessを仮定し、その取得費用・実現性は別管理 |
| 比較 | RF0/RF1/EW2と、同じ情報を使う強い交換子ノルム保証 |
| 目的 | 認証stepの差と、それを得るための証拠取得費用を明らかにする |

### 重要な区別

**固定DFモデルを対象とすることと、元の電子Hamiltonianに対する厳密保証を得ることは別です。**

固定されたbinary64係数を数学的に正確な係数として解釈する場合も、その意味、元データからの変更、演算時の丸め・数値誤差を明示してください。

DFモデル内の保証を、元の分子Hamiltonianに対する保証へ無条件に拡張してはいけません。

また、exact ground状態を条件付き入力とすることは、量子回路による状態準備が無料であるという意味ではありません。

**state accessの条件付き理論比較と、実際のend-to-end資源評価を区別してください。**

## 3. Task A：認証対象モデルの完全な仕様

既存のDFHamiltonianを基点として、次のデータが一つの固定identityで対応するよう、入出力仕様を設計してください。

1. 元データと固定DFモデルの識別情報
2. constant・nuclear repulsion・energy origin
3. 一体演算子とsigned DF平方
4. fermion modeの順序と符号規約
5. 対象sectorとその保存条件
6. Hermiticityとその検証方法
7. PSD化に伴うscalar shift
8. 各fragmentとPF適用順序
9. 必要な誤差・丸め台帳

特に、既存preflightで問題となった次の区別を維持してください。

- `DFHamiltonian` と `DFModel` のデータ規約
- full one-body/constantとcorrection-only表現
- `df_truncation_value` とscalar correction
- spin-orbital入力とspatial入力
- 数値Hermitizationと、元入力がHermitianであることの証明
- 古典sector制限と、量子回路が同じsectorを保存すること

**既存SOURCEに不具合があると未確認のまま断定しないでください。**

今回作るのは、これらを安全に接続するための仕様であり、既存コードの修正ではありません。

## 4. Task B：PSD分割・下界・上界の認証仕様

次の形を対象にします。

\[
H_{\mathrm{DF}}=LI+\sum_jF_j,
\qquad
0\preceq F_j\preceq f_jI.
\]

既存K0の既知PSD化手順を利用し、正符号DF平方、負符号DF平方、一体項のそれぞれについて、必要な認証条件を整理してください。

### 4.1 PSD分割

各fragmentについて以下を仕様化します。

- 元演算子との対応
- PSD化のために必要なscalar
- PSD性の証拠
- 対象sectorでの保存条件
- 指数化回路との対応
- 証拠生成と検証の費用

一般SOS分割を新しく探索・最適化しないでください。

### 4.2 下界L

一体項のsector下界と、負符号DF平方に必要な上界を使う既知構成を前提に、Lの生成・検証手順を設計してください。

保存するcertificateには、少なくとも次が必要です。

- 対象モデル・sector・分割のidentity
- 下界の導出方法
- 使用した係数とその誤差
- scalar shiftの全内訳
- 正しい丸め方向
- 証明・検証に必要な補助情報

### 4.3 上界UとW

同じDF Hamiltonianとsectorに対する、検証可能な変分上界Uを得る手順を設計してください。

候補となるtrial state、正規化、expectation、数値誤差、stateがsector内にある証拠を明示してください。

既存HF energyやFCI保存値を、そのまま厳密な認証上界と呼んではいけません。

\[
W=U-L
\]

は、認証済みのLとUが同じ対象を参照する場合にのみ構成可能とします。

**今回は実際のL/U/Wを計算しないでください。**

## 5. Task C：f_j・Λ・K_SOS・Cbar2の接続仕様

以下の各量について、既存SOURCEを利用できる部分と、新しく必要な証拠生成・検証処理を区別してください。

### 5.1 Fragment上界

\[
0\preceq F_j\preceq f_jI,
\qquad
\Lambda=\sum_jf_j
\]

を同じPSD分割に対して認証する仕様を作ってください。

既存のfloat norm helperと、数学的に認証されたoperator上界を混同しないでください。

また、shift前のnormをshift後のPSD fragmentにそのまま使わないでください。

### 5.2 K_SOS

既存K0の係数辞書、行和上界を再利用します。

- 入力fragmentの順序
- BCH係数
- 重複添字の扱い
- 上界計算
- 有限精度の安全性
- 計算量・保存量
- 出力certificate

を仕様化してください。

新しいK_SOSの定理や計算法を研究する必要はありません。

### 5.3 Cbar2

同じS2順序に対応する、

\[
\overline C_2\ge C_2
\]

の認証手順を設計してください。

単純なtriangle boundだけでなく、同じ情報から取得可能な可換性・fragment構造を対照側にも利用できるようにしてください。

**相対形式側だけを精密に評価し、比較相手へ意図的に粗い認証値を与えてはいけません。**

### 5.4 共通certificate identity

L/U/f_j/Λ/K_SOS/Cbar2について、同じモデル・sector・PSD分割・PF順序・係数規約を参照していることを検査できる設計にしてください。

入力が異なる場合は比較不能と分類し、自動的に値を流用しないでください。

## 6. Task D：保証・step選択への接続

以下の既存保証を、共通certificateから評価するための仕様を作成してください。

\[
\eta_0(h)=
\frac{32(h\Lambda)^2}{1-16(h\Lambda)^2}
\]

\[
\eta_1(h)=
h^2K_{\mathrm{SOS}}+
\frac{512(h\Lambda)^4}{1-16(h\Lambda)^2}
\]

およびEW2、既存の強化交換子対照：

\[
b_C(h)=
\frac{h^2\overline C_2}{1-h\Lambda/2}.
\]

ただし、適用条件とlog branch・有限step領域は元監査を正本とし、数式を勝手に一般化しないでください。

### 出力設計

- 各保証の成立条件
- 必要な認証入力
- 認証付き最大十分stepの定義
- 比較可能・比較不能の判定条件
- 失敗したcertificateの理由
- 使用した保証・数式・SOURCEへの追跡情報

相対形式保証に有利な結果が得られなくても、証拠・出力を保持する仕様にしてください。

今回、新しいhや比較値は計算しません。

また、RF0/RF1/EW2とCbar2の比較だけで、best-known baseline全体を超えたと判定する仕様にしないでください。

他の適用可能な低エネルギー保証やQPE回路安定性の比較を、未評価事項として残してください。

- phase branch・absolute energy origin
- QPE readoutと失敗確率
- 回転合成・実装誤差
- certificate生成・検証の古典費用
- 証拠や回路の再利用・償却条件

異なるaccessモデルを混同しないでください。

**第一段階の条件付き比較で得られた結果を、状態準備込みの総資源優位として報告できない設計**にしてください。
