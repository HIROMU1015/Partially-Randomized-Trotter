元の検証コードや保存済み照合記録は変更しない。固定URLの組み立てとbytes比較には既存検証と同じ標準ライブラリ方式を使い、
科学モジュールのimport・実行や、当時のbranch HEADの再照会を必要としない読み取り専用の入口を追加した。

リポジトリ内から、既存の公開ファイルを読む場合：

```bash
python3 scripts/verify_archived_publication_bytes.py --case e-r3-preparation
python3 scripts/verify_archived_publication_bytes.py --case b3-api-preflight
```

固定objectが既にローカルのGit管理領域にある場合は、ネットワークを使わず確認できる：

```bash
python3 scripts/verify_archived_publication_bytes.py --case e-r3-preparation --local-git /path/to/repository
python3 scripts/verify_archived_publication_bytes.py --case b3-api-preflight --local-git /path/to/repository
```

`--local-git`はobjectの読み取りだけを行い、fetchや参照更新はしない。必要なobjectがなければ失敗する。
通常のmain cloneに過去の科学SOURCE履歴がすべて含まれるとは限らないため、その場合は上の固定公開URLによる確認を使う。

対象は原リスト中の5 MiB以下の文書・Python SOURCE・JSON等のテキスト記録と、リスト原本そのものに限定する。
raw/checkpoint/cache領域、bundle分割part、log、バイナリ等は対象外とし、除外pathを出力する。
`PASS_SELECTED_FIXED_PUBLICATION_BYTES`は選択した公開bytesの一致を示す。原リスト全体の再検証、
科学条件の適合性、原結果の再解析、実行互換性、当時のbranch HEADの存在、科学的GOを示すものではない。
過去の照合記録を上書きせず、標準出力だけを返す。

他の旧出版確認・科学launcherにも、実行時のcheckout branchを照会する処理が残っている。
それらは当時の実行contextを記録した原版として保持する。保存済み結果の閲覧と、旧手順の再実行は区別し、
この補助コマンドを実行認可・再開条件・mandatory STOPの代替には使わない。

今回の技術確認では、E-R3の52ファイル（元リスト56件中、対象外4件）、B3の89ファイル
（元リスト126件中、対象外37件）と、各リスト原本を、既存Git objectと固定公開URLの両方で照合した。
選択141ファイル・3,834,091 bytesはすべて一致した。対象外はlog・XML・bundle分割part等であり、
全原データ・全履歴の再検証はしていない。改変・欠損・異なるcommit参照・空の検証範囲・対象外データの非読取りに関する6テストを確認した。
