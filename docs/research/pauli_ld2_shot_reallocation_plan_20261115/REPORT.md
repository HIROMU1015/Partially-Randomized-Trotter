## 2. 出発点にするBの2つの生成規則

Bの決定論PF計画（`7f27e18f` §3）と、その採択後の実装（`06f4210e` `scripts/run_pf6_cost_budget_q3_fixed.py`の`generate`）をそのまま使う。

```text
A_SHAPE（元の配分形状を保つ）    w[m,a] = VP[m]
B_PRICE（価格を考慮して振り替える） w[m,a] = VP[m] / C_ref[m,a]

N[m,a](λ) = max(1, min(VP[m], floor(λ w[m,a])))
予算 B に対し、Σ N C_ref ≤ B を満たす最大の breakpoint を選ぶ
```

- 上限 N ≤ VP は、Bの PF設計（N ≤ N0）と同じ初回の探索領域である。CPU・RAMの制限ではない。
- 価格は B2 の26軸モデル参照価格 C_ref（`a7eceecb`の`AXIS_TABLE.json`）を使う。凍結係数がX/Yで同一なので、生成される列もX/Yで同じになる見込みだが、X/Yは別々に生成・計上する。
- riskの単調性や、riskを見たλの調整は使わない。整数制約で使い切れない分は「未使用予算」として記録する。

## 3. PFの結果から分かったこと

Bの12件（`b4296b110` REPORT §2）では、同じ3/4予算で次の差が出た。

| PF候補・規則 | m10・m11・m12 のshot数（各軸） | 判定 | MSE上界（Ha²、表示） |
|---|---|---|---:|
| S2・B_PRICE | 19・13・4 | 適合 | 約1.50×10⁻⁶ |
| Yoshida4・B_PRICE | 19・7・2 | 適合（τに近い） | 約2.42〜2.43×10⁻⁶ |
| M5・B_PRICE | 13・5・1 | **モデル不適合（下界>τ）** | 約4.90×10⁻⁶ |
| 各公式・A_SHAPE | 全roundを約3/4に縮小 | 適合 | 約0.97〜1.53×10⁻⁶ |

最終roundを大きく削った列ほどMSEが上がり、m12を1 shotまで削ったM5は不適合になった。PFとPauliは信号・normalizationが違うので、この結果をLD2へそのまま移すことはできない。ただし、**最終roundのshot数が判定を左右しうる**ことを示す実例である。

## 4. 公開済みの値から読める予算の性質（計画用の算術）

以下は、公開済みのモデル参照価格（`a7eceecb` AXIS_TABLE）を足し合わせただけの計画用の値である。新しい価格・Q3・費用確定ではない。

| 量 | 値（RZ、モデル参照） |
|---|---:|
| 全軸 N=1 の総額（どの配分でもこれより下げられない） | 約 322,379,320 |
| m0〜m9 を VP のまま保った部分 | 約 180,706,976 |
| m10・m11・m12 を各軸 N=1 にした部分 | 約 17,572,687 ／ 62,415,679 ／ 233,914,358 |

ここから次のことが読める。
- **PFの最小費用のどちらも、全軸 N=1 の総額を上回る**ので、生成が空（BUDGET_MENU_EMPTY）になることはない。
- **PFの既達成費用のどれを予算にしても、m12 は N=1 になる**（A_SHAPEでもB_PRICEでも。m12を2 shotにする余地は無い）。m12 だけで予算の約38%（Full PF最小）〜約54%（p7最小）を占める。
- B0I p7 の最小（435,481,090）では、m0〜m9 を VP、m10〜m12 を N=1 にした額（約 494,609,700）をすでに超える。B_PRICE は m10〜m12 を N=1 にしたうえで、m9 以前も VP より削ることになる。
- Full PF の最小（615,304,502）では、m0〜m9 を VP、m10〜m12 を N=1 にしても約 120,694,802 の余りがあり、主に m10 へ数shotを戻す形になる。
- A_SHAPE では全roundを一様に約13%〜18%へ縮めることになり、m0〜m4 も一桁のshot数になる。
- 自身の費用を3/4にする予算（約2,533,877,262）は、PFの最小費用の約4〜6倍である。B_PRICE では削減が m12 に集中し、m12 は9から数shotへ下がる見込みである。

具体的な整数列と条件付き費用は、実行の開始時に生成し、Q3の前にcommitで固定する（BのPF6と同じ手順）。

## 6. 提案：最初に試す予算

**第1段（推奨、新規Q3 2件）：FPN-B と OWN-B**

1. **PFに届くかの評価は、FPN-B を先に試す。** PFの最小費用はどちらでも m12 が1 shotになり、PFではその形（M5・B_PRICE）が不適合になった。LD2 でも「m12 が1 shot で閾値を満たせるか」が要になる。FPN-B は PFの最小費用のうち最も大きい予算で、m12 以外に最も多くのshotを残せる。ここで適合しなければ、より小さい予算の P7N-B（各成分が FPN-B 以下になる列）が適合する見込みは低い（riskの単調性は仮定していないので、証明ではない）。
2. **自身の費用を下げる評価は、OWN-B を同時に試す。** PFとの比較の結論は変えないが、FPN-B が不適合だった場合に、LD2 がどこまで費用を下げられるかの最初の手がかりになる。PFでは S2・B_PRICE（m12 を11→4）が適合したので、LD2 で m12 を9から数shotに下げても閾値を保てるかは、PFとの対比として意味がある。
3. 2件ともVPより各成分が小さい列なので、既存の追跡範囲に収まり、1件あたり数分で済む見込み（VPは約160秒）。並列に実行できる。

**結果に応じた次の段（それぞれ別の承認、各1〜2件）**

| 第1段の結果 | 分かること | 次の候補 |
|---|---|---|
| FPN-B 適合 | B_PRICE の1列で、LD2 は条件付きで Full PF の最小費用以下になれる | P7N-B（1件）で p7 の最小費用に届くかを確認。主張は m10〜m12 の外挿価格に依存する（§7）ので、価格側の根拠（A の S1、C2 の採否）を先に固める |
| FPN-B 不適合、OWN-B 適合 | PFの最小費用には届かないが、m12 を数shotに下げても閾値は保てる | 間の予算を1点だけ試す（例：PFの元配分の費用 838,693,580。A_SHAPE なら m12 が2 shot残る）。m12 を守る別の生成規則は、Bの2規則の外なので別計画 |
| 両方不適合 | この2規則では、PFの最小費用にも、自身の3/4予算にも届かなかった（方式全体の否定ではない） | OWN-A（1件）で形保持の一様縮小を確認。上限をVPより上げる設計（早いroundのshotを増やす）は別計画 |

**一括で進めたい場合**：FPN-B・P7N-B・OWN-B・OWN-A の4件を並列に実行してもよい（独立job、数分）。ただし P7N-B は FPN-B が不適合なら判断に寄与しにくい。

新規Q3の件数：第1段 2件（推奨）、一括なら4件、全段の合計でも最大6件。

## 7. m10〜m12 が外挿であることの扱い

- **Q3の判定は配分 N だけで決まり、価格には依存しない。** 価格が影響するのは、(a) どの整数列を生成するか、(b) その列の費用 T(N) の2点である。外挿の不確かさは、Q3の適合・不適合を変えない。
- 一方で「LD2 が PF より安い」という主張は、T(N) に含まれる m10〜m12 の外挿価格に依存する。PFの最小費用を予算にした列では、m12（N=1）だけで予算の約38〜54%を占める。
- そこで各列について、T(N) を次の2つに分けて報告する。
  - m0〜m9（q≤512）：凍結モデルの参照値。構造は S0+ により q=512 まで確認済み（`2d3aa21f5`：stepあたり定数1900 RZ・切片308 RZ が q=512 でも一致）。
  - m10〜m12（q≥1024）：未観測の外挿。
- 判断の余裕として、**反転に必要な外挿部分の相対誤差** r = (B_PF − T(N)) / T_{m10–12}(N) を併記する。m10〜m12 の真の価格がモデル値より r 以上高ければ、PFより安いという結論は崩れる。
- 比較するPF側の60軸も、条件付きの閉包価格である（2%保証なし）。双方の価格の条件を併記する。
- 価格がモデル値と違っても、生成した列は配分として有効なままである（最適な振替ではなくなるだけ）。

## 9. 判定とSTOP

- 判定はVPと同じ：有効上界≤τで適合、下界>τでモデル不適合、跨げばINCONCLUSIVE、必要なgateの不成立はUNKNOWN。
- 結果は「この候補・この規則・この予算で評価した1列」の判定であり、十分N・最適N・物理的RMSE・正式G・winnerには昇格しない。
- 費用は CONDITIONAL_FIXED_ALLOCATION_COST（モデル参照価格による条件付き費用）として、Q3判定と別に記録する。
- **実行時のSTOP条件**：承認された件数の完了、または重大な入力・gate・保存・資源の異常。無断のretry、結果を見た予算・列・範囲の変更、次段への自動進行はしない。予算が空、価格の欠落、列の重複は、生成時に保留または統合する。
- **本計画はここでmandatory STOP。** 新規Q3・compile・再fitは別指示とする。
