# 2026-08-25 回路cost追加検証batch

## 目的

connected K1--K3モデルで残っている三点を、同一のH4-chain DF Hamiltonian snapshotと
同一compiler条件で切り分けて検証する。これは近似cost modelの局所検証であり、最終総cost評価ではない。

## 実行する検証

1. **A: $K=2$の複数order-2条件**
   - $L_D=0$、event列長4と6。
   - 全order patternを強制生成し、全order-0、order-2が1回、2回以上の三scopeを評価する。
   - 各長さで50、各single patternで50、各multi patternで20標本とする。
2. **B: $L_D=6$の独立K4**
   - 既存の不通過transfer条件に対し、4-event窓のfull/triple/pair/singleを同一trajectory上で対応付ける。
   - all-order-0とorder-2がちょうど1回の5 patternを各30標本採取する。
   - 旧L4残差fitとは異なり、holdout残差から係数をfitしない。
3. **C: controlled反復の$q=8$ holdout**
   - $L_D=3$、$\delta=0.1$、$r=4$、$K=0$。
   - $q=1,2$を各150標本で較正し、未使用$q=8$を150標本で検証する。

## 実装と再開方法

`scripts/run_rte_cost_data_batch.py`がAとBを並列実行し、それらの終了後にCを実行する。
各jobのcommand、時刻、return codeは`plan.json`と`status.json`へatomicに保存する。
Bは固定sample chunk、checkpoint、SQLite metric cacheを使うため中断後も同じcommandで再開できる。
個別logは`logs/`、成果物候補は`outputs/`に保存する。

## 追加batchの完了結果

- Batch Aの独立K1--K3推定は、$L_D=0$、$K=2$でRZ主誤差12.376%、全metric最大
  21.426%、最大z 1.787だった。最大誤差は複数order-2ではなくL6全order-0に現れたため、
  構造的なK1--K3不足と独立係数のMonte Carlo誤差を分離できない。
- Batch Bの$L_D=6$独立paired K4は各pattern 30標本で、固定holdoutに対する全metric最大点誤差を
  1.281%へ下げた。RZの予測側95%半幅は最大4.110%、95%上側診断は5.714%なので精度追加が必要。
- Batch Cの$q=1,2$ affineから未使用$q=8$への予測は、全metric最大0.0529%、RZ 0.0280%、
  最大z 0.243、RZ 95%上側診断1.091%で暫定5%条件を通過した。

## follow-up batch

次の結果を最終costと切り離して採取する。

1. $L_D=0$のL4/L6全order patternについて、同じtrajectoryのfull回路と1--3 event局所窓から
   paired残差を求める。全order-0とsingle-order-2は各pattern 10、multi-order-2は20標本とする。
2. $L_D=6$のK4を各5 pattern 500標本へ増やす。既存30標本のfixed chunkとpersistent cacheを再利用する。
3. 固定K1--K3 calibrationを未使用L8の全order-0 1500、single-order-2各位置500標本でholdoutする。
4. 同じ独立K4をL8へ加え、K1--K4の点誤差、z、予測半幅、95%診断を評価する。

`scripts/run_rte_cost_followup_batch.py`が1と2を並列実行し、その後3、4を順に実行する。
live status、log、checkpoint、成果物候補は`artifacts/rte_cost_followup_batch/2026-08-25/`へ保存する。

## follow-up batchの完了結果

上記4 jobはすべてreturn code 0で完走し、専用validatorを通過した。

1. **$L_D=0$の複数order-2 paired再検証**
   - H4 chain、距離1.0 Å、STO-3G、DF rank 12、short-step 0.025、$K=2$。
   - $L=4,6$の全Taylor patternを同一trajectoryのfull回路と1--3 event局所窓で比較した。
   - 全metric最大点誤差1.679%、主RZ最大z 6.703、主RZの点wise正規近似95%上側診断3.201%。
   - 先行する独立係数推定の最大21.426%超過は、複数order-2に固有のcluster構造破綻を
     示す結果ではなかった。
2. **$L_D=6$のK4精度増加と未使用$L=8$**
   - 同じH4 snapshot、short-step 0.025、$K=2$で4-event各patternを500標本へ増やした。
   - 固定K1--K4の未使用$L=8$評価は全metric最大点誤差3.750%、主RZ最大z 2.290、
     主RZの95%上側診断7.045%だった。
   - 点誤差5%は通過するが、独立係数の予測不確かさを含むrigorousな5%保証ではない。
3. **controlled $q=8$**
   - $q=1,2$ affine modelから未使用$q=8$への全metric最大点誤差0.0529%、RZ 0.0280%、
     主RZの95%上側診断1.091%だった。

さらに、$L_D=6$、$L=8$を同一trajectoryのK1--K4局所窓とfull回路で直接比較する
paired構造検証を別batchで行った。all-order-0を100、exactly-one-order-2を各位置20標本とし、
全metric最大点誤差4.008%、主RZ最大z 10.630、主RZの95%上側診断4.902%だった。
高いz-scoreは小さい高次残差が非ゼロであることを示すが、相対5%内という運用条件は満たした。

## 2026-08-25時点の判断

- H4ではK1--K3を既定候補とし、holdoutが5%点基準を外れた$L_D=6$だけK4へ進む。
- K4を全条件へ一律に追加しない。
- paired結果はmodel構造の検証、独立calibration/holdoutは運用推定器の検証として分ける。
- exact DF Hamiltonian snapshotとcompiler条件を再現単位とする。
- これらは回路cost proxyのlocal検証であり、RPE shot、誤差配分または最終総costではない。

主成果物は`artifacts/rte_cost_followup_batch/2026-08-25/`および
`artifacts/rte_cost_paired_k4_l8/2026-08-25/`に保存した。runtime cache、checkpoint、logは
再開用であり、結果JSON、plan、status、snapshot、生成・検証コードを証拠単位とする。
