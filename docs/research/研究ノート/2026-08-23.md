# 2026-08-23 ランダム回路cost加法モデルのpilot検証

## 目的

最終総コスト評価へ進む前に、ランダム回路のcompiled costを小さい回路のコスト和で
近似できるかを調べる。特に、次の二つを分離して検証した。

1. RTE occurrence全体の一体compile対、個々のRTE eventを別compileしたコスト和。
2. partial-$S_2$全体の一体compile対、決定論forward half、RTE occurrence全体、
   決定論reverse halfを別compileした3部分のコスト和。

## 実装

- `src/trotterlib/random_circuit_cost_validation.py`にversioned validation payload、
  paired comparison、完全列挙対MC比較、fingerprint検査を追加した。
- `scripts/run_random_circuit_cost_validation.py`にH-chain実行driverを追加した。
- 完全列挙とMC、複数の標本数の間でtranspile cacheを共有した。
- 広いgridを高速に走査するため、RTE occurrence比較だけを実行するscopeを追加した。
- process間でDF回路表現がcanonicalでないことが判明したため、複数条件で一つのHamiltonianを
  再利用するbatch実行を追加した。
- 専用testは3件がpassした。関連する既存cost testを含む最新実行は53件がpassした。

## pilot条件

H4 chain、距離1.0 Å、STO-3G、DF rank 12、$L_D=3$、$\delta=0.1$、$q=1$、
$K=0$とした。compilerはQiskit 1.3.0、basis gates `rz,sx,x,cx`、optimization level 1、
結合制約なし、transpiler seed 17である。古典MC seedは20260822とした。

## 結果

### $r=1$の完全列挙

218 trajectoryを完全列挙した。partial-$S_2$の3部分加法モデルは一体compileを全metricで
過大評価し、相対差は約$2.5\times10^{-7}$--0.987%だった。最大はRZ depthの0.987%だった。

100標本MCの一体compile期待値は完全列挙値から最大0.213%ずれ、最大absolute z-scoreは
約2.41だった。30から100標本で観測誤差が単調減少したわけではないため、MC停止条件は
まだ決めない。ただし、加法モデル相対誤差の100標本推定値は完全列挙値から最大0.021
percentage point以内だった。

### $r=2$のevent境界

trajectory空間は$218^2=47{,}524$なのでMCを用いた。$r=1$と同じDF回路表現を共有した
100標本batchでは、個々のeventを別compileして足した値がRTE occurrence一体compileを
全metricで48.30--57.58%過大評価した。paired differenceのabsolute z-scoreは
15.86--17.79だった。別processの異なるDF回路表現で行った300標本replicateでも
52.99--61.15%の過大評価、30.19--32.18のabsolute z-scoreを得た。

同じ$r=2$の100標本で、RTE occurrenceを一つの部分として用いるpartial-$S_2$ 3部分和の
過大評価は0--0.959%だった。

再生成中に、同じH4、距離、basis、DF rankでも別processの`preparation_hash`が一致せず、
絶対compiled costと加法誤差の細部が変化することを確認した。したがって、異なるhashの
artifactをMC収束比較として混ぜず、主な$r=1,2$比較は同じHamiltonianを共有したbatchに
置き換えた。process間で比較する場合はDF表現のcanonicalizationが別途必要である。

## 判断

個々のRTE eventを独立なcost単位として足すモデルは採用しない。少なくともRTE short-step列を
まとめたoccurrence全体をproxyの最小較正単位とする。partial-$S_2$の
「forward half + RTE occurrence + reverse half」は安価な初期近似として残し、一体compileとの
差を境界補正または推定不確かさとして較正する。

この判断はH4の1条件だけに基づくpilotであり、一般的なproxy受理ではない。最終コスト評価、
量子shot、controlled Hadamard回路、ノイズまたは実backendを評価したものでもない。

## 性能上の判断

$r=1$完全列挙は420秒、MCを含むartifact全体は696秒だった。$r=2$でpartial-$S_2$を含む
30/100標本は299秒だった。RTE-occurrence-only scopeの300標本は85秒だった。
以後は軽量scopeで広いgridを先に走査し、代表点だけ重いpartial-$S_2$または反復回路評価へ進む。

## 次に行うこと

1. H4の$L_D=1,3,6$、$\delta=0.05,0.1,0.2$、$r=2,4$を
   RTE-occurrence-only scopeで走査する。
2. $K=2$を追加する。
3. 代表点で300/1000標本を比較してMC停止条件を決める。
4. 代表点で$q=2,4$のstep間非加法性、controlled回路、compiler条件依存を検証する。

## 02:02 JST：RTE境界補正cluster modelのholdout検証

### 目的

上記pilotで不採用としたevent単純和に、隣接event間の相殺を平均的な境界補正として
加えれば、RTE occurrence一体compile期待値を予測できるか調べた。さらに、3 event以上に
またがる効果が無視できるかを、較正に使わない長いevent列で確認した。

### 実装

- `src/trotterlib/rte_boundary_cost_validation.py`に、1--3 event clusterの係数、
  独立holdout、標準誤差伝播、versioned/fingerprinted payloadを実装した。
- `scripts/run_rte_boundary_cost_validation.py`と専用test 2件を追加した。
- 全長でshort-step時間とevent分布を固定し、長さによる物理parameter変化と境界数の変化を
  混同しないようにした。
- 最初のrunは浮動小数点丸めで有限分布dataclassの完全一致判定が失敗した。event order、
  確率、dimensionless short-step時間をtolerance付きで比較するよう修正し、結果を生成し直した。

### 条件

H4 chain、距離1.0 Å、STO-3G、DF rank 12、$L_D=3$、$K=0$、short-step時間0.025、
Qiskit 1.3.0、optimization level 1、結合制約なしとした。$C_1$は218 eventを厳密列挙し、
$C_2,C_3$を各300標本で較正した。未使用の$C_4,C_6$を別seedの各300標本で評価した。

### 結果：確認済み

- event単純和のholdout最大絶対相対誤差は157.51%、最大absolute z-scoreは48.21だった。
- pair境界補正では8.73%、1.50まで低下した。
- triple補正では4.06%、0.52まで低下した。
- 隣接eventが同じDF fragmentとなる確率は0.73106で、最大fragmentの確率は0.85055だった。
- pair補正は全metricで負で、1-event期待値の66.1--73.0%に相当した。
- triple残差は1-event期待値の$-3.09$--$+2.93$%で、全metricで自身の推定標準誤差より
  小さかった。triple補正はcount/sizeを改善したが、depthではpair補正より一様に良くなかった。

したがって、単純和の過大評価はMC標本不足ではなく境界相殺による系統差であり、この1条件では
expectation-level pair補正で大部分を説明できたと判断する。pair補正を次の最小model候補とし、
triple項は高次境界効果の診断用に残す。受理閾値は決めず、他の$L_D,\delta,r,K$、compiler、
controlled条件への一般化もしない。

artifactは
`artifacts/rte_boundary_cost_validation/h4_sto3g_d100_rank12_ld3_dt0p1_ref4_k0_v1.json`
で、fingerprintは
`0fdb2a859a83c1aae9c8f8fcf58cfc54b0168e45e8a7d06ef7b2d90b5084d0d1`である。
実行時間は557秒だった。dirty local worktree evidenceであり、immutable CI evidenceではない。

最新のlocal全test suiteは`.venv311/bin/python -m pytest -q`で
`449 passed, 4 warnings`だった。warning 4件は既存grouped-UWC testのcomplex-to-real castである。

### 次に行うこと

1. $L_D,\delta$とshort-step時間を変え、pair係数を未使用条件へ移送できるか調べる。
2. $K=2$へcluster schemaを拡張し、可変event長で同じ局所補正が成立するか確認する。
3. optimization level、結合制約、controlled回路をholdoutにする。
4. 代表点で標本数を増やし、proxy受理閾値とMC停止条件を決める。

## 16:25 JST：1000標本・複数seedとfragment境界層別化

### 目的と実装

300標本pilotのpair残差がMC揺らぎかを判定し、境界補正をfragment確率から構成するため、
次を実装・実行した。

- `estimate_compiled_occurrence_cost`へ、各sampleのevent列とcompiled costを読み取る任意の
  observerを追加した。既存呼出しでは無効で、従来集計を変更しない。
- `rte_boundary_pair_validation_v1`として、same/different-fragmentおよび有向fragment pair別の
  境界補正をonline集計し、calibrationとholdoutを別seedにした。
- 親processで生成した一つのH4 Hamiltonianを3 workerへ渡し、1000標本のfull clusterを
  独立2 seed、pair層別を1500/1500標本で並列実行した。
- 全workerの`preparation_hash`一致を必須とした。

小規模spawn smokeでは、H2の非常に小さいTaylor residualに対して既存cluster検証の
浮動小数点閾値が厳しすぎる境界ケースを確認した。H4の本検証条件では発生していない。
H2へ一般化する前にtolerance policyを別途修正する。

### H4条件

距離1.0 Å、STO-3G、DF rank 12、$L_D=3$、$K=0$、short-step時間0.025、
Qiskit 1.3.0、optimization level 1、結合制約なしとした。新しい三artifactはすべて
`preparation_hash = 400b18b...98d44`で一致した。以前の300標本artifactはhashが異なるため、
prefix収束比較としては使わない。

### full cluster結果：確認済み

| seed | pair最大誤差 / z | triple最大誤差 / z |
|---:|---:|---:|
| 20260823 | 8.07% / 2.96 | 2.33% / 0.79 |
| 20261823 | 8.18% / 3.02 | 3.73% / 0.97 |

pair-onlyの系統差はRZ/CX countとcircuit sizeで両seedに再現した。depthではpair-onlyの
最大z-scoreは1未満だった。triple補正は全metric・両seedでz<1だったが、$\mu_3$自体の
absolute z-scoreは最大1.40であり、非ゼロを確定したとは扱わない。

したがって、depthではpair-onlyを候補として残し、count/sizeではtripleを次の候補とする。
count/size用$\mu_3$は追加の$C_3$ calibrationまたは未使用$L=8$で再確認する。

### fragment層別結果：確認済み

same-fragment解析確率は0.7310604だった。1500標本calibrationから求めた補正を別seedの
1500標本pair holdoutへ適用すると、different補正をゼロとするsame-only modelは最大誤差
3.65%、最大z 2.59だった。same/different双方を使う二分類modelは最大誤差0.849%、
最大z 0.587だった。

RZ countの条件付き補正はsameで-321.79、differentでも-25.62だった。sameが主要因だが、
different確率が約26.9%あるため無視できない。`fragment-3→fragment-3`が解析確率72.344%を
占める一方、主要な異種pairにも負の補正がある。

### 判断

1. pair係数はsame-onlyで構成せず、少なくともsame/differentの二分類を使う。
2. 長いevent列のmodel次数はmetric別に扱う。depthはpair候補、count/sizeはtriple候補とする。
3. 受理閾値はまだ決めず、$L_D,K$、compiler、controlled条件へ一般化しない。
4. 次はcount/sizeの$\mu_3$精度または$L=8$ holdoutを確認してからparameter gridへ進む。

1000標本workerは約2324、2341秒、pair層別workerは約1019秒だった。並列化によりwall timeは
約39分に抑えた。成果物と詳細は`docs/rte_boundary_pair_validation.md`に記録した。

最新のlocal全test suiteは`.venv311/bin/python -m pytest -q`で
`451 passed, 4 warnings`だった。warningは既存grouped-UWC testのcomplex-to-real castである。
