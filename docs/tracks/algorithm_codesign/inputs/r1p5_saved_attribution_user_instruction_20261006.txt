# 3. 問いB：\(G_Q\) 改善要因の分解

R1で保存された値について、

\[
G_Q = N_{\rm total}\,E[C_Q]
\]

の関係を利用し、A / ordinary、A / PTSC-K0を分解してください。

対象：

\[
Q\in\{T,CX,1Q\}.
\]

各登録条件について、少なくとも

\[
\frac{G_Q^A}{G_Q^B}
=
\frac{N_A}{N_B}
\frac{E[C_Q]^A}{E[C_Q]^B}
\]

を保存してください。

ここでBはordinaryまたはPTSC-K0。

これにより、

- shot-count側の改善
- per-shot native cost側の改善

を厳密に分離してください。

## 3.1 shot側の入力も保存

shot数は非線形なので、

\[
N_A/N_B
\]

をさらに恣意的に一意分解しないでください。

代わりに、shot ruleの入力として：

- \(B^2\)
- \(B\)
- synthesis/coefficient bias upper
- remaining axis budget
  \[
  s=\epsilon_{\rm axis}-b
  \]
- sufficient shot count

を並べてください。

必要なら「B²が低い」「biasが低い」などの方向だけを記述してください。

**結果後に独自のcausal percentage attributionを作らないでください。**

## 3.2 特に見る登録条件

最低限、以下を詳しく比較してください。

### x = 1/4, epsilon = 1e-3

A / ordinary:

\[
G_T \approx 0.796
\]

A / PTSC-K0:

\[
G_T \approx 0.823
\]

となった条件。

ここで、

- normalization差
- shot差
- \(E[C_T]\)差
- bias差

のどれがどの程度の方向に効いているかを明示してください。

### x = 1/8, epsilon = 1e-4

AがT側では有利だが、CX側ではtrade-offになる条件。

ここでは、

- T-count reduction
- shot数
- CX event cost

の競合を整理してください。

# 5. precisionごとのbias / shotの関係

登録precisionが厳しくなると、

- synthesis errorは減る
- bias marginは増える
- shotsは減り得る
- 一方でT-countは増える

というtrade-offがあります。

各arm/xについて、

\[
\epsilon_{\rm synth}
\rightarrow
(
b_{\rm synth},
N,
E[C_T],
G_T
)
\]

を一覧化してください。

特に、

> 最も厳しいnative precisionが必ず最小 \(G_T\) ではない

ことを、保存値が支持するか確認してください。

これはRA-RTEで

\[
\text{representation parameter}
+
\text{synthesis precision}
\]

を共同設計する必要性を判断する材料です。

ただし新しいprecision optimizationは今回行いません。
