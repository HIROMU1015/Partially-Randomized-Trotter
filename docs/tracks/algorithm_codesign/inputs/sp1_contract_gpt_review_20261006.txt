# 3. 必須修正①：fusion policyを「role依存禁止」ではなく完全共通化する

現在案には、

> D/R横断fusionは禁止する

という記述があります。

これは避けた方がよいです。

理由は、将来もしD/R境界で同一generatorが隣接した場合、

- NONEでは融合可能
- D/R placementではroleを守るため融合禁止

となると、**placement labelそのものが回路費用差を人工的に作る**可能性があるためです。

## 推奨する正式fusion rule

science sourceでは次の順序に固定してください。

\[
\boxed{
\text{logical sequence}
\rightarrow
\text{joint-space lowering}
\rightarrow
\text{canonical exact fusion}
\rightarrow
\text{placement mask}
\rightarrow
\text{PAI}
}
\]

canonical fusionは、

> **隣接する完全に同じjoint-space generatorだけをexactに融合し、signed angleを加算する。**

とします。

つまり、

\[
R_Q(\theta_1)R_Q(\theta_2)
=
R_Q(\theta_1+\theta_2)
\]

のみ。

許可：

- 同一generator
- 隣接
- exact angle addition
- angle 0なら削除

禁止：

- commuting gateの並べ替え
- D/R labelを理由とした順序変更
- maskごとに異なるfusion
- 結果を見てfusion strategy変更

### 今回のregistered domainでは

A/BはPauliを交互にしており、Cも

\[
D:Z,\quad R:X,\quad R:Z,\quad R:X
\]

なので、**おそらくcross-role exact fusion opportunityは0**になります。

それをsource freeze前に機械的に監査してください。

保存すべきものは各pathについて、

- pre-fusion native sequence
- fusion candidate count
- actual fusion count
- post-fusion sequence
- D/R provenance

です。

理想的には今回、

> `cross_role_fusion_opportunities = 0`

が全registered pathsで成立するようにします。

これならD/R fusion policy自体がscience resultへ混入しません。

# 4. 必須修正②：「whole-wrapper actual T count」という呼び方を狭める

現在のproposalではSP-0.5で保存されたsingle-primitive gate stringsのT-countを足してwrapper costを作ります。

しかし現段階では、

- full wrapperをClifford+T列として組み立て
- primitive境界を越えたT/T† cancellation
- Clifford simplification
- peephole optimization

までは行っていません。

したがってprimaryを、

> **actual whole-wrapper T count**

と呼ぶのは少し強すぎます。

## SP-1では次の名前に固定することを推奨

> **fusion-normalized additive synthesized-primitive T cost**

数式的には、

\[
C_T^{\rm add}
=
C_{\rm fixed,T}
+
\sum_i C_{T,i}^{\rm stored}
\]

です。

これは、

- logical exact fusionは先に済ませる
- 各残存native rotationにはSP-0.5の実際の合成列/T-countを使う
- ただし**異なるprimitiveのClifford+T sequence間の追加最適化はしない**

というmetricです。

この限定を入れればSP-1として十分です。

### 代案

もし「actual wrapper T count」と呼びたいなら、全maskについて実Clifford+T sequenceを連結し、同一のdeterministic reducerをかける必要があります。

ただ、今回はそこまで広げる必要はありません。

**SP-1はaccumulation mechanism pilotなので、additive synthesized costで十分**です。

actual compiled/simplified wrapper costは、SP-1が有望だった場合の次stageで評価すればよいです。
